---
title: CREATE INDEX
---

Creates an index on a table expression.

Indexes help ScopeDB prune or accelerate eligible reads. They are not uniqueness constraints, global secondary indexes, or row lookup indexes.

## Syntax

```scopeql
CREATE <index_type> INDEX [ IF NOT EXISTS ] [ <name> ] ON <table_name> (<index_expression>)
[ COMMENT = '<string_literal>' ]
[ WITH ( '<property_name>' = <literal> [, ...] ) ]
```

## Parameters

### `<index_type>`

The type of index to create:

* `POINT`: supports pruning or acceleration for eligible point-style predicates on the indexed expression. On `object` and `any` expressions, a point index can also support eligible predicates on nested paths inside the value.
* `RANGE`: supports eligible range predicates on the indexed expression.
* `PATTERN`: supports eligible string pattern predicates.
* `SEARCH`: supports eligible text search predicates using the `search` function.
* `MATERIALIZED`: stores the result of an expression so ScopeDB can reuse it during eligible reads.

### `<name>`

The name of the index.

This is optional; if not provided, a default name will be generated based on the table and expression.

The index name must be unique within the table.

### `<table_name>`

The name of the table on which to create the index.

### `<index_expression>`

The expression to index.

## Examples

```scopeql
-- Create a table with different column types
CREATE TABLE logs (
    id int,
    time timestamp,
    message string,
    level string,
    var object,
);

-- POINT index on a column
CREATE POINT INDEX ON logs (id);

-- POINT index on an object column and its nested paths
CREATE POINT INDEX ON logs (var);

-- POINT index on a timestamp expression
CREATE POINT INDEX ON logs (trunc(time, unit => 'hour'));

-- POINT index on a single hot semi-structured path
CREATE POINT INDEX ON logs (var['type']::string);

-- RANGE index on a timestamp column
CREATE RANGE INDEX ON logs (time);

-- SEARCH index for text searching in log messages
CREATE SEARCH INDEX ON logs (message) WITH ('analyzer' = 'log');

-- MATERIALIZED index on a semi-structured path
CREATE MATERIALIZED INDEX ON logs (var['host']::string);
```

## When to Use Each Index Type

1. Use `POINT` indexes when:
   - Queries frequently filter on exact values for a column or expression.
   - Queries need to filter nested paths inside an `object` or `any` expression.
   - You want pruning or index acceleration for eligible point-style predicates.

2. Use `RANGE` indexes when:
   - Queries frequently filter a column or expression with range predicates.

3. Use `PATTERN` indexes when:
   - You need to optimize supported string predicates such as `contains`, `starts_with`, `ends_with`, or compatible `regexp_like` forms.

4. Use `SEARCH` indexes when:
   - You need to perform text search operations using the `search` function.

5. Use `MATERIALIZED` indexes when:
   - You have complex expressions or semi-structured data paths that are expensive to compute.
   - You want ScopeDB to store expression results for eligible reads.

## Notes

- Indexes add storage and maintenance work.
- Eligibility depends on the indexed expression, predicate shape, and data layout.
- Do not assume every predicate on a nested value receives the same pruning or acceleration behavior.
- Put index design guidance in performance optimization docs. Keep this page focused on `CREATE INDEX` syntax and public behavior boundaries.
